# Benchmark suite runs as a single sequential job

A benchmark "suite" (one button → llama_bench + spec + MTP runs auto-selected by model capability) executes as **one** `JobKind::Benchmark` job whose inner fn calls the existing per-type `*_inner` fns sequentially, sharing a single `Arc<Job>` for logs/SSE. Rejected alternatives: (a) client-side loop over the three endpoints — fragile (tab close kills the suite) and fights the JobManager's single global active slot with 409s; (b) a job queue — real concurrency isn't wanted for GPU benchmarks anyway, and a queue is unneeded complexity (YAGNI). Consequences: the backend process spawns/tears down per sub-run (~3× model load time, accepted); sub-runs are linked by a `suite_id` column; suite status follows the success/partial/failed rule with continue-on-error between sub-runs.
