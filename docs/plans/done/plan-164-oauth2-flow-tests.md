# OAuth2 Login Flow Tests Plan

**Goal:** Add ~16 tests covering the five untested OAuth2 login-flow functions in `crates/tama-core/src/proxy/auth.rs` — `build_oauth2_client_from_config` (:396), `fetch_userinfo` (:413), `handle_login` (:509), `handle_login_callback` (:568), `handle_logout` (:667) — which today have zero test coverage despite being ~260 lines of security-critical code.

**Architecture:** All tests go into the existing `#[cfg(test)] mod tests` at the bottom of `crates/tama-core/src/proxy/auth.rs` (:706), reusing its imports (`tower::util::ServiceExt`, `axum::{routing::get, Router}`) and the established local-axum-mock pattern (`test_non_tama_bearer_still_validates_authentik`, :1321) plus `wiremock` 0.6 (already a dev-dependency; usage pattern at `crates/tama-core/src/backends/updater.rs:229,397-418`). Handlers are mounted on minimal per-test routers WITHOUT `auth_middleware` — the middleware's skip-path behavior is already covered by `test_login_routes_in_skip_paths` (:1105). No production code changes.

**Tech Stack:** Rust, Axum, tokio, wiremock, tower, oauth2 5.0, cookie

**Key facts discovered while reading the code (do not "fix" these in tests):**
- All three handlers redirect with `StatusCode::FOUND` (302), never 303.
- Cookie names: `SESSION_COOKIE_NAME = "tama_session"` (:306), `CSRF_STATE_COOKIE_NAME = "tama_oauth2_state"` (:308). State is generated by `oauth2::CsrfToken::new_random` inside `handle_login` (:533) and stored in a signed cookie scoped `Path=/login/callback`, `Max-Age=300`; the callback re-verifies the HMAC signature with `state.cookie_key` before comparing it to the `state` query param (:617).
- Error redirects go through `redirect_to_login_error(reason, description)` (:463) → `302` to `/login/error?reason=<r>&description=<d>` with `percent_encoding::NON_ALPHANUMERIC` encoding (spaces become `%20`; the word `state` is unchanged).
- `fetch_userinfo` is deliberately fail-soft: malformed JSON, non-2xx, and network errors all return `("unknown", None)` with a `warn!` log (:425-459) — the callback then issues a session for username `"unknown"` instead of erroring. Tests pin this behavior as-is; changing it is a product decision, not part of this test plan.

```rust
/// Helper: ProxyState with OAuth2 enabled and caller-provided endpoint URLs.
fn make_login_flow_state(
    authorize_url: String,
    token_url: String,
    userinfo_url: Option<String>,
) -> Arc<crate::proxy::ProxyState> {
    let config = crate::config::Config {
        proxy: crate::config::ProxyConfig {
            oauth2: crate::config::types::OAuth2Config {
                enabled: true,
                client_id: "test-client".to_string(),
                client_secret: "test-secret".to_string(),
                authorize_url,
                token_url,
                userinfo_url,
                redirect_uri: "http://localhost:11434/login/callback".to_string(),
                scopes: vec!["openid".to_string(), "profile".to_string()],
                session_ttl_secs: 3600,
                ..Default::default()
            },
            ..Default::default()
        },
        ..Default::default()
    };
    Arc::new(crate::proxy::ProxyState::new(config, None))
}

/// Helper: minimal router mounting the login-flow handlers directly
/// (no auth_middleware — these handlers are its skip-path targets).
fn login_flow_app(state: Arc<crate::proxy::ProxyState>) -> Router {
    Router::new()
        .route("/login", get(handle_login))
        .route("/login/callback", get(handle_login_callback))
        .route("/logout", get(handle_logout))
        .with_state(state)
}

/// Helper: GET /login and return (state query param, "tama_oauth2_state=<v>" cookie pair).
async fn start_login(app: &Router) -> (String, String) {
    let resp = app
        .clone()
        .oneshot(Request::builder().uri("/login").body(Body::empty()).unwrap())
        .await
        .unwrap();
    assert_eq!(resp.status(), StatusCode::FOUND);
    let location = resp
        .headers()
        .get(header::LOCATION)
        .unwrap()
        .to_str()
        .unwrap()
        .to_string();
    let url = url::Url::parse(&location).expect("authorize URL must parse");
    let state = url
        .query_pairs()
        .find(|(k, _)| k == "state")
        .map(|(_, v)| v.into_owned())
        .expect("authorize URL must contain state param");
    let set_cookie = resp
        .headers()
        .get(header::SET_COOKIE)
        .unwrap()
        .to_str()
        .unwrap()
        .to_string();
    let pair = set_cookie
        .split(';')
        .next()
        .unwrap()
        .trim()
        .to_string();
    assert!(pair.starts_with(&format!("{}=", CSRF_STATE_COOKIE_NAME)));
    (state, pair)
}
```
(`url` is already a dependency of tama-core — `crates/tama-core/Cargo.toml:22`, used at `crates/tama-core/src/config/resolve/mod.rs:130`.)

### Task 2: `handle_login_callback` CSRF/state validation tests (no mocks)

**Context:**
The callback validates, in this exact order (:574-634, comparison at :617): (1) `tama_oauth2_state` cookie present AND signature-verifies, else `redirect_to_login_error("state", "CSRF state missing")`; (2) `code` query param, else `("code", "Authorization code missing")`; (3) `state` query param, else `("state", "State parameter missing")`; (4) `state` param equals the cookie value, else `("state", "CSRF state mismatch")`. All four failure exits happen BEFORE any token exchange, so no mock server is needed — but tests (2)–(4) must first run a real `GET /login` (via Task 1's `start_login`) to obtain a legitimately signed state cookie, because the callback rejects unverifiable cookies as "missing". This is the CSRF-protection core of the login flow.

**Files:**
- Modify: `crates/tama-core/src/proxy/auth.rs` (tests only)

**What to implement:**

Tests (all use `make_login_flow_state` with dummy `https://auth.example.com/*` URLs — never contacted — and `login_flow_app`):

1. `test_callback_without_state_cookie_errors` — GET `/login/callback?code=abc&state=xyz` with NO Cookie header → 302; `location` starts with `/login/error?reason=state` and contains `CSRF%20state%20missing`.
2. `test_callback_with_forged_state_cookie_errors` — same but with header `Cookie: tama_oauth2_state=attacker-controlled` (not signed by `state.cookie_key`) → same `reason=state` / `CSRF%20state%20missing` redirect (unsigned cookies are indistinguishable from absent ones).
3. `test_callback_missing_code_errors` — `let (_state, pair) = start_login(&app).await;` GET `/login/callback?state=whatever` (no `code`) with `Cookie: <pair>` → `location` starts with `/login/error?reason=code` and contains `Authorization%20code%20missing`.
4. `test_callback_missing_state_param_errors` — `start_login`; GET `/login/callback?code=abc` with the cookie → `reason=state`, `State%20parameter%20missing`.
5. `test_callback_state_mismatch_errors` — `let (real_state, pair) = start_login(&app).await;` GET `/login/callback?code=abc&state=wrong-state-value` with the cookie → `reason=state`, `CSRF%20state%20mismatch`. Also assert `real_state != "wrong-state-value"` so the test can't pass vacuously.

Assertion helper to avoid repetition:
```rust
fn assert_login_error_redirect(resp: &Response, reason: &str, description_fragment: &str) {
    assert_eq!(resp.status(), StatusCode::FOUND);
    let location = resp.headers().get(header::LOCATION).unwrap().to_str().unwrap();
    assert!(
        location.starts_with(&format!("/login/error?reason={}", reason)),
        "expected /login/error?reason={} redirect, got {}",
        reason, location
    );
    assert!(
        location.contains(description_fragment),
        "expected description containing {:?}, got {}",
        description_fragment, location
    );
}
```
Remember descriptions are percent-encoded with `NON_ALPHANUMERIC`: pass `CSRF%20state%20missing` etc. as fragments.

### Task 3: Callback token-exchange and userinfo tests (wiremock)

**Context:**
The happy path (:636-662) exchanges the code at `oauth2_config.token_url` via `oauth2_client.exchange_code(code).request_async(&state.client)` and then calls `oauth2_config.userinfo_url` via `fetch_userinfo`; both URLs are config-driven, so wiremock supplies the provider. The token endpoint is exercised loosely — match only `method("POST")` + `path("/token")` (the oauth2 5.0 crate sends client auth as a Basic header and a form body; coupling the test to either would test the crate, not Tama). Two behavior contracts get pinned here: (a) token-endpoint failure → `redirect_to_login_error("token", ...)`; (b) userinfo failure is fail-soft by design (`fetch_userinfo` :425-459) — the callback still issues a session, with username falling back to `"unknown"` or to `nickname`/`name` claim aliases (:434-444). Do NOT "fix" (b) to an error redirect; the test documents the deliberate degradation.

**Files:**
- Modify: `crates/tama-core/src/proxy/auth.rs` (tests only)

**What to implement:**

Add `use wiremock::matchers::{method, path};` and `use wiremock::{Mock, MockServer, ResponseTemplate};` to the test module imports.

Session-verification helper (mirrors `extract_session` at :352-370):
```rust
/// Decode and verify a tama_session Set-Cookie value against the state's signing key.
fn decode_session_cookie(set_cookie: &str, state: &crate::proxy::ProxyState) -> SessionClaims {
    let pair = set_cookie.split(';').next().unwrap().trim();
    assert!(pair.starts_with(&format!("{}=", SESSION_COOKIE_NAME)));
    let mut jar = cookie::CookieJar::new();
    jar.add_original(cookie::Cookie::parse_encoded(pair).unwrap());
    let verified = jar
        .signed(&state.cookie_key)
        .get(SESSION_COOKIE_NAME)
        .expect("session cookie must verify against state.cookie_key");
    serde_json::from_str(verified.value()).expect("session claims must be valid JSON")
}

/// Run the full login+callback flow against a wiremock provider; returns the
/// callback response.
async fn run_callback(app: &Router) -> Response {
    let (state, pair) = start_login(app).await;
    app.clone()
        .oneshot(
            Request::builder()
                .uri(format!("/login/callback?code=test-code&state={}", state))
                .header(header::COOKIE, pair)
                .body(Body::empty())
                .unwrap(),
        )
        .await
        .unwrap()
}
```
