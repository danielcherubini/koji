# SvelteKit Frontend Migration Plan

**Goal:** Replace the Leptos/WASM frontend (~29K lines Rust, 5.1MB binary) with a SvelteKit + TypeScript + Tailwind CSS frontend (~10K lines, ~120KB JS).

**Architecture:** SvelteKit app lives in `crates/tama-web/ui/`. Builds to `ui/build/` via Vite. Embedded into tama-cli via `include_dir!`. API routes (`/tama/v1/*`) stay in Rust/Axum — zero changes to backend.

**Tech Stack:** SvelteKit 2, TypeScript strict, Tailwind CSS v4, Vite, pnpm, Svelte 5 runes.

---

## Pre-Flight

Before starting tasks, verify the environment:

- [ ] `pnpm` is installed: `pnpm --version` (should be ≥ 9)
- [ ] Node.js is installed: `node --version` (should be ≥ 20)
- [ ] Current frontend builds: `make build-frontend` (Trunk + WASM)

8. **`src/lib/api/client.ts` — fetch wrapper with CSRF:**
   - `getCsrfToken()`: Read from `document.cookie` (parse `tama_csrf_token`), fallback to `localStorage['_tama_csrf_token']`
   - `storeCsrfToken(token: string)`: Save to `localStorage['_tama_csrf_token']`
   - `apiFetch(path: string, options?: RequestInit)`: Prepend `/tama/v1`, inject CSRF headers, store CSRF from response `X-CSRF-Token` header
   - Export `api` object with `get`, `post`, `put`, `delete` convenience methods
   - `post` and `put` should auto-JSON-stringify body if object
   - All methods return `Response` — caller does `.json()`

9. **`src/lib/stores/toasts.ts`:**
   - Interface `Toast { id: string; severity: 'info' | 'success' | 'warning' | 'error'; title: string; message: string; durationMs: number; }`
   - `export const toasts = writable<Toast[]>([])`
   - `addToast(title, message, severity?, durationMs?)` — adds to store, auto-removes after duration
   - `removeToast(id)` — removes from store
   - `clearToasts()` — clears all
   - Max 5 toasts (remove oldest when exceeded)
   - Use `crypto.randomUUID()` for IDs

10. **`src/lib/stores/downloads.ts`:**
    - Interface `DownloadEvent { event: string; job_id: string; filename?: string; repo_id?: string; bytes_downloaded?: number; total_bytes?: number; size_bytes?: number; duration_ms?: number; error?: string; }`
    - Interface `ActiveDownload { job_id: string; filename: string; status: string; bytes_downloaded: number; total_bytes?: number; }`
    - `export const activeDownloads = writable<ActiveDownload[]>([])`
    - `export const downloadHistory = writable<any[]>([])` — will be typed properly in Task 4
    - `handleDownloadEvent(event: DownloadEvent)` — processes SSE events:
      - Started/Progress/Verifying: update activeDownloads in-place
      - Completed/Failed/Cancelled: fetch fresh history from API
      - Queued: fetch fresh active downloads from API
    - Start EventSource connection to `/tama/v1/downloads/events` on browser init (check `$app/environment` browser flag)
    - Export `startDownloadEvents()` and `stopDownloadEvents()` for lifecycle control

11. **`src/lib/components/Sidebar.svelte`:**
    - Replicate current sidebar behavior from `crates/tama-web/src/components/sidebar.rs`:

   ```ts
   import { writable } from 'svelte/store';
   import { browser } from '$app/environment';
   import type { MetricSample } from '$lib/types/metrics';

   export const metricsHistory = writable<MetricSample[]>([]);
   export const metricsError = writable<boolean>(false);

   let eventSource: EventSource | null = null;

   export function connectMetrics() {
     if (!browser || eventSource) return;
     eventSource = new EventSource('/tama/v1/system/metrics/stream');
     eventSource.addEventListener('snapshot', (e: MessageEvent) => {
       metricsHistory.set(JSON.parse(e.data));
       metricsError.set(false);
     });
     eventSource.onerror = () => { metricsError.set(true); };
   }

   export function disconnectMetrics() {
     eventSource?.close();
     eventSource = null;
   }
   ```
